# 个人本地编码助手：轻量收尾方案

状态：已实施（2026-09-06）。Phase 1 费用保护（unknown 保留风险、输出限制送达、
重启新批次拒启）、Phase 2 工具小修（超发修复/唯一结果目录/文档勘误）、Phase 3
个人 5 项验收均完成，并修复 Phase 3 发现的治理 RemoveMessage 崩溃缺陷。
预算 ¥2，实际 ¥0.10。结论：可以个人日常使用（报告见
`tests/performance/.run/personal4/report.md`）。

## 1. 定位与结论

NovaMind 面向个人本地使用，交互形态参考 Claude Code。当前目标是可靠地读代码、改文件、执行工具、保存会话和处理失败，不是建设多人高并发服务。

允许现在开始日常试用。正式收尾只解决直接影响花费、数据安全和结果可信度的问题；不再把完整性能压测作为个人使用的前置条件。

范围以本文为准：原 `REAL_MODEL_LOAD_TEST_PLAN.md` 保留为历史设计和可选扩展，不再要求完成其全部负载矩阵。没有执行的阶段继续标记未验证，不能改写成全部完成。

### 本轮做与不做

| 本轮做 | 本轮不做 |
| --- | --- |
| 修压测脚本的费用保护、输出限制和超发 | 并发 8、固定到达率、极限吞吐测试 |
| 校正隔离与费用描述，保留最小可复核结果 | 新建监控平台、调用追踪系统或跨进程账务服务 |
| 做少量真实个人任务验收 | 强制 30 分钟稳定性、生产 SLA、Docker 验收 |
| 记录实际使用痛点再优化 | 为未来规模预先改数据库或执行器架构 |

重要边界：`tests/performance/` 的 BudgetController 只保护经该包装器运行的测试调用，不等于正常 GUI/CLI 已有统一硬预算。本轮不将它扩展为产品级计费系统。日常使用依靠供应商支持的额度限制及账单检查；没有硬限制时不得承诺金额绝不超出。

## 2. Phase 0：确认真实落点（实施前必读）

已核对的接口与模式：

- `tests/performance/harness.py`：`BudgetController.try_reserve()`、`settle()`、`CallRecord`、`estimate_cost()`。复用现有锁和预留流程，不另造预算框架。
- `tests/performance/metered.py`：`MeteredChatModel._invoke_one()`、`_ainvoke_one()`、`_finish()`。同步和异步路径都需覆盖异常收尾。
- `novamind/core/provider.py`：`get_provider(..., **kwargs)` 向实际模型构造器透传参数。参数名称按安装版本和所选模型支持范围核对，不向 `/chat` 塞入不存在的配置字段。
- `tests/performance/real_model_server.py`：`build_metered_llm()`、`precheck()`；目前预检没有真正验证输出上限。
- `tests/performance/real_model_load.py`：`run_ladder()`、`summarize()`、`main_async()`；复用 httpx，不增加压测依赖。
- `tests/unit/test_real_model_load_harness.py`：沿用现有免费测试形式，但 unknown usage 用例必须验证金额，而不只是计数。
- `novamind/core/config.py`：源码模式日志仍在源码根目录；`docs/session-model.md` 定义跨重启持久化和删除失败契约。

## 3. Phase 1：修最必要的费用保护

### 3.1 未知 usage 不按免费处理

在现有 `settle()` 中区分两条分支：

1. 输入和输出 usage 完整有效：按配置单价结算并释放对应预留。
2. usage 缺失、部分缺失或费用无法确认：保留该笔风险金额，不释放后继续当作免费调用；记录 unknown 状态及预留值。

建议沿用 pending 保存未知风险，报告明确 pending 包含“仍在途”和“已结束但费用未知”。不引入复杂结算服务。实际 usage 超过预留时必须如实记账并停止后续准入，不能截断到预算内。

同步异常和异步取消都留下记录；异步 CancelledError 收尾后仍重新抛出。同步 invoke 在线程中被外层取消时，保留其在途预留，等待真实调用结束结算，不重复释放。

### 3.2 把输出限制传到真实模型

在 `build_metered_llm()` 中显式传入经过验证的输出上限、请求超时和重试设置。测试实例建议初值：

- 最大输出 2000 token，与预留上限共用同一个配置来源；模型不支持时预检失败，不能静默忽略。
- 请求超时 60 秒、SDK 自动重试 0；这是小样本测试配置，不修改日常应用默认值。
- 金额及单价必须为有限有效数；拒绝 NaN、无穷大、非正预算及无效价格。

当前按消息字符数估算输入且未计工具定义，不能称保守硬上界。优先使用已安装模型提供的计数能力并计入绑定工具；无法可靠计数时明确标记估算并保留余量，不为此自建完整 tokenizer 系统。

单价不继续默认为其他模型的历史价格。付费测试前显式填写当前模型单价、币种和核对日期。无法核对时只允许免费预检，不以“估算很低”为由继续升压。

### 3.3 重启不默默恢复成全额预算

采用最简单的防误操作方案，不实现持久化账本：

- 启动付费实例时，如果目标 calls.jsonl 已非空，直接拒绝启动，提示保留旧记录并核对已花费用。
- 需要续测时，用户核对供应商用量和未结算调用后，指定新的批次目录及剩余额度；不能自动沿用原来的完整金额。
- 每次新批次要求显式填写 `--budget`，不依赖默认 ¥10。文档说明这是单批次预算，不是整个账号的总限额。
- 预检不写付费调用日志，不污染真实运行批次。

未知费用、预留和真实费用都只是本地保护依据，不宣称能终止已提交到供应商的任务或消除延迟出账。

### 本阶段验证

免费测试覆盖：预留后 unknown 仍占额度；部分 usage；异常与取消；正常结算只释放一次；无效预算；非空日志拒绝复用；模型构造实际收到输出/超时/重试参数；预检不调用模型。测试保护逻辑不能用真实付费请求验证。

禁止事项：放宽敏感日志规则、取消安全检查、修改日常模型默认值、重启时删除旧记录来绕过检查。

## 4. Phase 2：小修压测脚本与记录

### 4.1 修超发与基本统计

- `run_ladder()` 在 await 发请求之前领取轮次编号；用固定长度工作队列或事件循环内无 await 的计数领取即可，不需要新调度框架。
- 不同并发档使用相同固定样本集合，而不是每个 worker 都从第一个样本重新开始。
- `--warmup`、`--baseline` 实际控制轮次数；零次正确跳过，无效负值拒绝。
- HTTP 非成功状态、error 帧、缺少 done、超时分别判定；主动取消结果也保存。坏 JSON 帧不得被悄悄跳过后算全成功。
- 百分位统一使用已说明的算法，例如 nearest-rank 的 ceil(n*p)-1；覆盖小样本边界，不报告小样本可靠 p99。

### 4.2 只保存必要证据

- 每次客户端运行创建唯一结果子目录，保存 turns.jsonl 与 summary.json，避免后续运行覆盖前一档。
- 逐轮只保留批次、场景、thread_id、状态、耗时和长度，不保存完整提示词或回复。
- 报告区分 chat 轮次和模型调用次数；模型 invoke 成功不能代替会话正确性验证。
- 日志写入失败必须可见，并停止新增测试调用，不能继续宣称记录完整。

### 4.3 如实说明隔离，暂不扩展核心配置

本轮选择透明披露共享日志这一限制：测试 workspace/数据库/office 独立，但源码模式 audit logs 仍在项目 logs；只允许无隐私测试材料。不能写“日志完全隔离”，也不能声称满足原方案的全路径隔离。

如果后续确实需要完全独立日志，再单独做源码快照运行或增加日志路径配置；本轮不为追求文档措辞改动核心路径体系。

### 本阶段验证

免费调度测试：并发 1/2/4、每档20时均恰好20；两次运行保留两组结果；HTTP失败、error→done、坏帧、取消不误报成功。文档去除“已完成完整压测”“实际费用 ¥1.27”“日志完全隔离”等证据不足的表述。

修改范围优先限定在 performance 工具、对应单测及相关文档；不重跑历史全部付费场景，不改写旧原始数据以迎合报告。旧报告保留并增加勘误，新报告引用修正后的证据。

## 5. Phase 3：个人使用验收，而非容量验收

Phase 1/2 免费验证通过后，按真实个人工作流做以下5项。默认单任务顺序运行；最多同时操作两个会话，不设响应时间硬 SLA。

| 场景 | 操作 | 通过标准 |
| --- | --- | --- |
| 读代码 | 在一次性小测试项目中解释函数及调用关系 | 指向真实文件和符号，不编造不存在的实现 |
| 改文件 | 修一个小缺陷，查看 diff 并运行该项目测试 | 只改指定区域；结果由文件和测试确认，不只看模型文字 |
| 失败恢复 | 触发一个可控的失败命令或读取不存在文件，再继续任务 | 失败明确可见，后续仍能执行，不把失败说成成功 |
| 停止与会话 | 停止一轮、继续同会话、切换另一个会话 | UI可恢复，无串话；不承诺停止立即停止计费 |
| 重启恢复 | 完成一轮后正常重启，再读取历史 | 已完成消息保留，无重复；失败/取消状态符合既有契约 |

先使用测试目录和无价值样例文件，不直接让模型修改重要未提交项目。浏览器验收中观察实际按钮与消息，而不是用静态字符串断言替代交互。

每项一次即可作为首轮冒烟，失败才针对性复测。执行前另行确认本批次模型和剩余金额；达到预算或调用无法排空时停止，不因“必须验收完”自动加钱。

验收后日常使用3至7天，只记录真实痛点：任务、预期、实际、是否影响文件/费用、能否复现。没有实际问题就不继续做结构性优化。

## 6. 最终验证与交付

1. 先运行现有免费入口：`python -m pytest tests/unit/test_real_model_load_harness.py -q`，加入本轮回归用例。
2. 如触及 provider/runtime，再跑相应现有测试；lint/type命令按仓库 CI 配置执行，不另造“通过”数字。
3. 执行 `git diff --check`，核对所有付费测试默认不运行、密钥未入结果文件。
4. 更新 performance README 和旧压测方案状态；只记录本轮真正运行的测试。原始结果保持本地，不提交密钥或私人材料。
5. 用户要求前不 commit、不 push，不发起新付费调用。

最终可给出的结论：

- **可以个人日常使用**：5项工作流可用，没有已知数据损坏或无法恢复问题；费用保护限制已明确。
- **带已知限制试用**：存在不影响文件和恢复的小体验问题，登记后继续使用。
- **先修再用对应功能**：发生越界写入、历史丢失或无法恢复；只阻塞受影响功能，不无差别要求重做整个项目。

优先顺序：费用保护 → 脚本与记录小修 → 5项个人冒烟 → 日常反馈。没有高并发指标和长期压测，也可以完成本轮个人使用验收。
