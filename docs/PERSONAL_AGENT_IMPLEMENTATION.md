# Personal Agent 本轮实施说明

依据：根目录 `NovaMind_Personal_Agent_任务书.md` v1.3。范围是个人使用的 NovaMind，而非新建另一套 Agent。

本轮状态：源码实现与单文件打包交付。按用户最新要求，不运行测试、不做鼠标/浏览器验收、不发起真实模型调用；不能将下文当作真实场景验收通过报告。

后续更新：用户在 GUI 优化轮明确要求自行测试。最新修复、离线门禁与窗口/浏览器检查范围见 [GUI 优化记录](GUI_REFINEMENT_REPORT.md)；下文保留初次实施时的事实记录。

## 1. 使用入口

- 本轮可执行程序：`dist-personal/nova-mind-gui.exe`，无需 `--desktop` 参数。
- 源码启动：`.venv/Scripts/python.exe -m entry.cli gui`；`desktop` 命令保留为统一桌面的另一个入口。
- Windows 默认统一管理工作台、悬浮球、快捷窗口、托盘、热键与提醒。没有单独的悬浮球 EXE。
- 默认热键 `Ctrl+Shift+Space` 打开通用对话，不读取剪贴板。明确选择翻译、解释、总结时才尝试获取选区；不能安全还原富文本/图片剪贴板时，不自动复制，改为手动粘贴。
- 关闭工作台或小窗口是收起；从托盘选择退出才退出程序。第二次启动唤醒既有实例。
- 沿用已有 `.env`。图片理解需要用户配置的模型实际支持视觉；本轮没有验证任何供应商的识图效果。

`dist-personal` 位于项目根目录下，与旧 `dist` 同级，因此按当前打包数据根约定，仍使用项目的 `workspace`；显式的 `NOVAMIND_DATA_ROOT` / `NOVAMIND_WORKSPACE` 覆盖继续生效。不要将 EXE 单独搬走后误以为仍会自动定位原工作区。

## 2. 已落地的功能

### 2.1 同一个 Agent，多种入口

完整工作台和助手小窗口的通用对话走同一个 `/chat`、WebRuntime、会话存储与容量限制；原有技能、沙箱、监控、诊断等入口保留。

翻译、解释、总结是轻量的单次模型动作；记录走完整 Agent 的真实日程工具，不是给改写换个名字。完成的快捷输入及回答通过同一 Agent 会话锁导入历史，稳定消息 ID 用于防止同一导入请求重复落盘。可以在工作台继续该会话，而不是重新执行一遍。

### 2.2 图片是通用对话输入

工作台和小窗口共享 `ui_common.js` 的附件组件：文件选择、Ctrl+V、拖入、缩略图、预览、移除与待发送状态。不会因为粘贴图片而自动发送，也不强制进入翻译。

- 支持 PNG、JPEG、静态 WebP；每条最多 3 张，每张最大 10 MiB，解码上限 2000 万像素。
- 服务端验证真实图片格式、调整 EXIF 方向，缩小至最长边 2560，转换为受控 JPEG 资源；这意味着会压缩，透明背景不保留。
- 聊天历史存资源引用及多模态结构；真正调用模型前才解析为图片数据，不能用文件名假装已识图。
- 同一历史继续向模型提供图片，支持追问与工作台续接。视觉调用失败会提示检查模型能力，不伪造识别结果；本轮没有实现 OCR 降级。
- 失败或停止保留当前输入草稿和图片；图片消息不进入后台自动候选抽取，明确要求记住另走受控记忆工具。
- 未发送、未设为图标的上传资源保留为草稿，桌面驻留时清理超过 7 天的废弃草稿；已发送图片和已保存图标不参与该清理。

### 2.3 日程记录与提醒

复用原 `task_store.py` 的 `tasks.json`、进程锁、原子写入与原日程工具，`heartbeat.collect_reminders` 由统一桌面生命周期调用，不增加独立日程库或后台安装服务。

- 创建、查询、修改、取消提醒；事件时间与 `remind_minutes` 提前量分开。
- 仅有日期时可保存 `todo`，明确没有定时提醒，继续询问时刻。
- 时间以本机时区解释；日期或上午/下午有歧义时由 Agent 询问，不宣称已经保存。
- 支持原有小时/日/周/月重复规则及有限次数。
- 到点投递本身不调用 LLM。通知交给原生托盘，同时持久保留未读记录。
- 退出/休眠后，下一次驻留检查会记录错过提醒；重复事项跳到未来，不逐条轰炸积压通知。
- 工作台日程页支持筛选、修改时间、完成、取消、已读；聊天显示日程结果卡片。
- 通知点击打开日程页。系统接受通知不代表用户已经看见，专注模式、系统开关仍可能隐藏通知；未读状态不因此清除。
- 私密模式限制的是个人长期记忆，不阻止用户主动创建日程，工具反馈会说明日程仍持久保存。

### 2.4 统一且可控的个人记忆

旧画像不再作为独立的活动注入来源。首次受控迁移将旧痕迹与旧画像登记进记忆治理；原文件保留，不整篇覆盖。

- 明确要求保存的单条偏好走治理服务；自动推断只生成候选，确认前不召回。
- 常用的回答语言、长短与代码解释偏好补充跨会话检索，不只依赖原句关键词重合；仍受状态、范围与条数/预算约束。
- 用户可以从记忆中心查看、确认、拒绝、禁用、修改、删除、导出和添加记忆。
- 修正/忘记工具与记忆中心共用服务。旧版本不能重新启用；墓碑和版本屏障阻止旧后台任务恢复已删除/已禁用内容。
- 支持 global 与项目范围，项目正文使用独立内容标识，不能因相同内容散列而串用项目状态。
- 全局召回开关、自动候选开关、预算写入统一设置；本次不记录/私密模式通过请求上下文约束实际读写。
- 全局停止自动候选不妨碍用户明确保存；私密则既不读也不写长期记忆。
- 本轮使用的记忆在消息中显示引用；历史只持久化引用 ID，重载时从治理服务读当前正文，已删除正文不再从引用接口显示。
- 普通删除是停止使用及墓碑，并不承诺磁盘擦除。另一个“清除正文”操作处理痕迹正文、派生索引、旧画像备份和本轮升级快照中的对应正文；不清除普通聊天历史、审计日志、系统备份或外部副本。

### 2.5 表达风格与悬浮入口

设置页提供默认、简洁、详细、温和、正式与自定义文字风格；默认保留 NovaMind 原有自然、简练的个人助手表达。全局设置同步到小窗口，完整会话可临时覆盖，不修改工具权限。

球、菜单和小窗口共享 `theme.css`、`desktop.css`、品牌 SVG 及线性图标。球不再是独立渐变字母；浅/深主题、空闲静止、悬停轻压、展开、贴边动效与真实任务状态接到桌面层。

工作台可配置当前显示、启动时显示、启动工作台、大小、透明度、主题、强调色、内置/自定义图标、完整适配/居中裁切、吸附、动效、状态、热键、位置和恢复默认。未点击应用不影响当前球。

原生位置计算使用球所在显示器的工作区，支持负坐标；改变大小同步原生窗口尺寸。系统减少动效与应用关闭动效也约束原生吸附动画。热键注册结果显示在设置页；字母热键需要 Ctrl 或 Alt，避免抢占正常输入。

开机自启默认关闭，只在打包程序内显式启用后写入当前用户 Windows Run 项；不安装另一个服务。源码模式不会登记不稳定的启动路径。

## 3. 数据与迁移

主要文件仍在原工作区：

| 数据 | 位置 |
|---|---|
| 对话、图片消息、快捷动作历史 | `state.sqlite3` |
| 痕迹正文 | 现有 MemoryConfig 的 `storage_path/traces.md`，默认 `memory_traces/traces.md` |
| 生命周期、版本与墓碑 | `memory_governance.sqlite3` |
| 原有日程及提醒状态 | `tasks.json` |
| 记忆/表达/桌面统一设置 | `personal_settings.json` |
| 图片与图标副本 | `attachments/` |
| 升级前快照 | `backups/personal-v1-时间-标识/` |

首次统一桌面启动或治理初始化，在持久化升级前创建快照：SQLite 使用 backup API，旧画像、痕迹与任务配置按清单复制。原文件不删除；`manifest.json` 记录来源。快照失败不会假装已经完成迁移。

本轮引入图片消息与消息引用的序列化标记。旧程序不一定能识别新版本消息，因此不要在同一个工作区同时运行新旧程序。需要回退时先退出程序、保留当前数据副本，再按升级清单将快照恢复到原路径；不要直接用旧 EXE 继续写入升级后的工作区。

## 4. 依赖与构建

新增图片验证依赖 Pillow，已同步 `pyproject.toml`、`uv.lock`、`requirements.txt`，锁定结果为 12.3.0。本地构建环境已安装该版本。

本轮打包命令：

```powershell
.venv\Scripts\pyinstaller.exe NovaMind.spec --noconfirm --distpath dist-personal --workpath build/personal-agent
```

只产生一个桌面入口程序，不另打包悬浮球。打包不等于窗口运行验收。

## 5. 由用户检查的重点

1. 双击本轮 EXE，查看工作台、球与托盘是否一起出现；再次启动是否只唤醒。
2. 浅/深主题、40/48/56 大小、图标裁切、拖拽/贴边、热键注册与多屏缩放效果。
3. 两个对话入口分别上传/粘贴/拖入图片，发送任意问题、停止、重试，并在工作台续问同一张图。
4. 使用实际支持视觉的模型，分别问无文字照片、软件界面、英文截图；本轮没有真实识图效果结论。
5. 先在日程页添加短时提醒，不依赖模型；收起工作台后观察通知、未读状态、点击定位、重复和错过提醒。
6. 对话创建/修改/取消日程，确认保存结果和日程页一致；只有日期时不得宣称已定时提醒。
7. 保存偏好后换会话；修改/禁用/删除，再检查召回；切换不记录/私密与全局记忆开关。
8. 退出再启动，确认历史、图片、风格、日程与悬浮球设置仍在原工作区。

本轮没有运行 Pytest、Node 行为测试、GUI 交互测试或真实模型验收。所做检查仅为 Python/JavaScript 语法、静态未定义名称/导入检查、前端本地资源引用与打包过程；不据此宣称功能已经验收通过。
