# GUI 优化与回归记录

日期：2026-10-22。范围：继续沿用 Personal Agent 工作区、Agent、技能、图片、日程和记忆能力，修复桌面入口与显示问题，并减少界面常驻控件。本轮用户明确要求自行测试；不沿用上一实施轮“未测试”的结论。

## 交互与视觉

- 工作台右上角增加「助手小窗」，通过同进程桌面桥打开，可携带当前会话；小窗已有未发送草稿时不会静默覆盖。旁边的「⋯」提供显示/隐藏球、找回球及桌面设置。
- 球的左键单击、Enter、Space 直接打开助手；右键、菜单键或 Shift+F10 打开翻译/解释/总结/记录等快捷菜单。拖动仍用于定位，贴边与动效设置保留。
- 下拉框统一为轻边框、圆角、选中标记、悬停和焦点状态；支持方向键、Home/End、Enter、Esc、Tab。原生 select 仍是值与事件来源，动态筛选和程序赋值会同步。
- 弹层支持向上展开、视口夹取和原生顶层 Popover（不支持时保留基础 details）；避免小窗或滚动区域裁切。选择过程中重建选项不会误关父菜单。
- 本轮资源使用统一版本标识，避免旧脚本缓存与新页面混用；无历史内容的小窗保留引导空态，不只留下空白区域。
- 工作台的记忆/项目范围/表达风格收进「对话选项」，私密与不记录状态仍可见。工具页面隐藏输入区但保留原节点与草稿，回到聊天继续使用。
- 小窗常驻仅保留附件、当前模式、选项和发送；停止按钮只在执行期间显示，复制只在有答案时显示，新会话与展开收进顶栏图标。翻译保留语言设置，记录仍走真实日程工具。
- 设置分为外观与折叠的「行为与启动」；重置动作收进更多菜单。日程、记忆条目使用操作菜单，原修改/完成/取消/已读以及记忆管理动作仍在。

## 已复现并修复的根因

1. `bring_to_front` 并不是当前 pywebview Window 的接口。原代码调用后异常被吞掉，导致显示后上下文同步、菜单可见标记等后续动作没有执行。移除无效调用，关键窗口打开失败记录日志并传回调用方。
2. WinForms 的 `move()` 自带显示窗口的效果。启动定位、页面就绪和尺寸同步改为先处理几何、最后明确恢复可见性，首次状态同步不再跳过。
3. pywebview 默认最小窗口是 200×100；球的预期窗口却只有 56–72px，导致透明命中区域过大、贴边计算越界。明确球窗口 `min_size=(56,56)`。
4. 原生监视器工作区为物理像素，pywebview 窗口坐标为逻辑像素。增加按窗口 DPI 换算和屏幕夹取；实际 150% 缩放环境下重置后球处于工作区内。
5. 保存外观时表单带回加载时的旧位置，后端又会把未传字段填成默认值。表单不再携带位置，后端保留省略字段；只有显式「找回」才重置坐标并显示球。
6. 程序重启后 WebView 可能保留旧 Cookie，守卫只为不存在的 Cookie 续发令牌，造成所有写入持续 403。现在仅在 Host/Origin 校验通过的读请求更新旧令牌；无令牌、旧令牌写入和外站来源依旧拒绝。
7. 空 `/chat` 请求会走到模型初始化。现在文字与图片至少存在一项，否则在边界返回 422，不初始化模型。
8. 小窗页面尚未完成加载时，打开请求可能提前清空待同步会话。现在只有确认前端入口已执行才消费该请求，页面就绪后继续同步；新增回归用例确认修复前失败、修复后通过。

没有替换 Agent、记忆算法、技能和日程业务。另移除了一个未使用导入，将请求上下文的共享可变默认值改为只读空映射。

## 截图反馈修复轮（2026-10-22，用户要求不运行测试）

以下为本次源码改动说明，不沿用上面的测试结果作为本次改动的验收结论。

1. **交付入口**：本轮开始时，实际运行进程来自 14:03 的 `dist-personal/nova-mind-gui.exe`，而非 18:04 的新版。用户退出旧程序后，统一更新 `dist-personal-ui/nova-mind-gui.exe`；旧 `dist-personal` 目录移入回收站。不迁移、不删除 `workspace/`、`logs/`、图片、聊天、记忆或日程数据。源码/打包版仍共用原数据根。
2. **小窗与球恢复**：小窗先恢复原生状态，再以目标窗口自身的 DPI 定位、校正屏幕范围，最后置顶显示；多 DPI 屏幕间定位球与面板时转换坐标。工作台重新打开也重新校正位置；显示球不再只调用 `show()`，而是重走位置、尺寸与可见性同步。状态轮询检测到“偏好要求显示，但原生窗口不可见”时恢复球。隐藏小窗与打开操作串行，关键定位失败写日志而非无声吞掉。
3. **设置对齐**：页面标题与表单共用 960px 居中内容轴；统一标签/控件列宽、开关右对齐、双列外观字段和窄屏单列，文字偏好输入框与按钮间距一致。
4. **输入区遮挡**：切换工具页时同步隐藏原输入区，不靠稍后的 DOM 观察器收尾；保留同一节点和草稿。聊天输入区居中并与消息区等宽，降低空输入框的默认高度，输入后仍随内容增长。
5. **五层记忆**：保留 Schema、衰减遗忘、检索、per-call 召回及后台沉淀。修正 L5 以裁剪后历史长度取模、只检查最后一条消息的问题：治理裁剪前将允许记录的纯文本用户消息加入有界的待抽取批次，同一用户轮只收集一次，满原配置批次（默认 10）异步抽取；待抽取批次在进程内状态中保存，不另建永久日志，重启不保证保留尚未抽取的批次。范围/治理 epoch 改变时重新开始批次，私密、不记录和图片不进入自动抽取。偏好、项目事实、任务上下文、经验均可成为候选；模型输出经过类型、长度和重要度校验，沿用分类衰减参数。候选仍须确认才可跨会话召回，删除/禁用屏障不放宽，不承诺记住所有聊天。
6. **审计双滚动**：限制审计布局为剩余可用高度，左右栏各有独立纵向滚动条，窄屏仍保留双栏；加载更新保留滚动位置，切换会话仅重置右栏。
7. **日程自适应卡片**：12 列网格，按描述长度分配 3/6/9/12 列；描述明确包含“重要/紧急/截止”等提示时至少 9 列，不新增或编造后端优先级。短事项可占 1/4 行，长事项可占 3/4；按实际内容区宽度降为双列/单列。完整描述与四项操作菜单仍保留，提醒业务不变，排序不变。

所有桌面页面资源版本统一为 `20261022ui2`，避免跨版本缓存混用。本轮仅进行代码检查、Python/JavaScript 语法检查及重新打包；未运行 pytest、Node 行为测试、浏览器或原生窗口点击验收，未发起付费模型调用。此前依赖审计的未处置告警仍见 [依赖审计记录](DEPENDENCY_AUDIT_2026-10-22.md)，不宣称打包版已通过安全验收。
