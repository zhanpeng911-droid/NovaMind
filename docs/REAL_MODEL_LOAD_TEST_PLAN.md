# 真实模型性能压测与验收方案

状态：历史设计与可选扩展。压测工具已实现并跑过一轮真实负载（见
`tests/performance/README.md`），但按 `docs/PERSONAL_USE_FINALIZATION_PLAN.md`
个人本地收尾方案，**不再要求完成本文档全部负载矩阵**；未执行的阶段（同
会话干扰、并发 8、30 分钟稳定性等）继续标记未验证。

依据：2026-09-06 检查的源码，基线提交 `8699157`。本文数字均为建议负载或拟定门槛，不是实测结果。历史回归通过数不等于性能验收结果。

## 1. 目标与边界

回答三个问题：本机在真实模型参与时能稳定支持多少并发；瓶颈位于供应商、排队、工具还是本地存储；是否可以按本地桌面使用范围验收。

- 所有计入压测结果的模型响应来自真实供应商，不用 FakeLLM 替代。
- 首轮固定一个供应商和模型，避免自动降级混入不同模型的耗时与价格；生产多模型路由另设专项。
- 测试对象是独立本地实例，单 Web 服务进程、仅监听 loopback，不打生产数据库或共享服务。
- 本轮不以公网服务、多人部署、Docker 或最大理论吞吐作为验收目标。
- 先取得基线再决定是否优化；不预先扩大并发、改 SQLite 配置或重写执行器。

## 2. 已确认的代码事实

| 事实 | 来源 | 对设计的约束 |
| --- | --- | --- |
| Web 容量默认 4，可由 `NOVAMIND_WEB_MAX_MODELS` 配置 | `novamind/webui/runtime.py`，`WebRuntime.__init__` | 先测试客户端并发 1/2/4；Web 容量不等于真实上游在途调用数 |
| 主模型通过 `asyncio.to_thread(llm_with_tools.invoke, ...)` 调用 | `novamind/core/agent.py`，`_call_llm` | 当前是节点结果 SSE，不测也不宣称真实 token TTFT |
| 多个可用 provider 会自动启用 researcher 路由 | `novamind/core/agent.py`，`_default_model_router`；`core/llm/model_router.py` | 仅设置 DEFAULT_PROVIDER/MODEL 不足以固定模型 |
| 摘要和记忆也可能调用模型，默认 middleware 模型与主模型路由可能不同 | `webui/runtime.py`；`core/context.py`；`core/memory/worker.py` | 一次 chat 不等于一次付费调用；所有模型路径都需要计量 |
| 源码模式忽略 NOVAMIND_DATA_ROOT；workspace 可配置，logs 仍位于源码根 | `novamind/core/config.py` | 仅设置 workspace 不能声称完成数据隔离 |
| `/chat` 请求仅包含 message/thread_id | `novamind/webui/server.py`，`ChatRequest` | 没有现成 HTTP 字段用于限制输出、重试、模型调用次数 |
| token_tracker 使用静态旧价格；日志敏感字段规则会遮盖 token 计数；token_usage 可丢弃 | `core/token_tracker.py`；`core/logger.py` | 现有审计日志和估算金额不能作为完整账单或预算熔断依据 |
| httpx 已在 requirements.txt 声明；已有 token benchmark 是模拟计数演示 | `requirements.txt`；`examples/benchmark_token_tracker.py` | 可复用 HTTP 客户端依赖，但目前没有现成真实模型压测命令 |

补充限制：取消 `to_thread` 的等待不保证终止供应商请求，也不保证停止计费。测试必须追踪取消后仍在途的调用，不能立刻补发大量请求。

## 3. 执行前必填项

真实调用开始前填写以下内容；缺少费用上限或无法确认隔离时禁止开始。

| 项目 | 要求 |
| --- | --- |
| 供应商、模型 | 精确模型 ID、端点域名、所在区域；主回复和辅助调用模型均列明 |
| 额度 | 本次金额上限及币种；供应商账号 RPM/TPM 等已知配额；是否与其他业务共享 |
| 单价 | 执行日核对供应商官方价格及链接；区分输入、缓存、输出、推理等实际计费项 |
| 机器 | CPU、内存、操作系统、电源模式、网络；Python 与依赖版本、源码 commit |
| 模型设置 | 温度、输入长度档位、实际 SDK 输出上限、超时、重试、工具调用上限 |
| 运行配置 | workspace、数据库、日志、临时文件、结果目录的解析后绝对路径 |

建议第一轮只跑 3 次预热和 10 次基线；根据实测耗时与费用预测后续阶段是否仍在授权预算内，再继续。没有指定金额时不填虚构价格或自动使用账号全部余额。

## 4. Phase 1：隔离实例与调用保护

### 实现内容

1. 从记录的提交制作独立源码快照，放到专用压测目录。不复制 `.env`、生产 workspace、日志或会话数据库。该动作不创建分支，不改主工作树。
2. 启动前设置独立 `NOVAMIND_WORKSPACE`，工作目录也放在压测区域；源码快照使默认 logs 与主项目隔离。检查所有相对写入路径和配置最终值，而非只检查环境变量名称。
3. 凭据从受控进程环境注入。在导入项目之前完成环境设置，防止多个 `load_dotenv()` 意外拾取其他配置；只输出非敏感配置摘要。
4. 拟新增测试启动器：复用正常 WebRuntime、Agent、middleware 和 SQLite 路径，通过最小构造注入固定模型及调用保护。若现有构造接口不足，单独增加可选依赖注入参数，默认行为保持不变，不复制一套服务逻辑。
5. 固定模型必须覆盖主回复、摘要和记忆路径，并输出解析后的路由链。禁用其他 profile 时遵循 provider_config 的实际配置名，不混用新路由和旧 provider 工厂的变量。
6. 对全部模型调用设置经该模型 SDK 验证的输出上限、超时和重试策略。建议单模型基线显式关闭自动重试及跨模型降级，以便准确归因；正常重试配置另测，不混入基线。
7. 工具阶段仅开放经过确认的本地测试工具及专属测试路径；禁止生产文件、任意外部写入、MCP 副作用和委派任务。若工具集合与日常配置不同，在报告中明确范围。

### 费用保护

- 拟新增全局 admission 控制：每次真实调用前预留保守的输入与最大输出费用；包含系统提示、工具定义、历史上下文及辅助调用。
- 预估已花费加在途预留达到预算 80% 时停止发起新轮次，等待已有调用收尾。余额不足以覆盖一次调用时，即使未到 80% 也拒绝该调用。
- 供应商支持账号级预算限制时一并配置；本地预估不承诺等于最终账单，也不保证覆盖延迟出账。
- 初始建议最多 300 个 chat 轮次、900 次真实模型尝试；单轮模型调用上限建议 6 次。达到任一上限停止准入。后台调用同样计数，不能绕过。
- 取消和失败请求不退回全部预留费用，直到取得真实 usage 或按保守上界结算；无法计量的调用标记 unknown，不算零费用。
- 不把提示词“回答少于 100 字”当硬输出限制，不把客户端超时当供应商请求已结束。

### 验证及边界

先在不发送网络请求的预检模式下验证路径、路由、预算拒绝和输出配置。再用一次真实调用检查实际模型、usage 与请求标识是否可采集；计入预热及费用。发现未受保护的模型路径则不得升压。

来源：config.py、provider.py、provider_config.py、model_router.py、runtime.py。禁止靠全局 monkeypatch 后宣称测到默认生产行为；任何配置偏差须写入运行清单。

## 5. Phase 2：压测客户端与指标采集

以下文件均为拟新增，当前不存在可直接运行的对应命令：

- `tests/performance/real_model_load.py`：显式启动的异步 HTTP/SSE 驱动、场景调度与报告输出；不自动进入普通 pytest。
- `tests/performance/real_model_server.py`：隔离启动和模型构造注入入口。
- `tests/performance/README.md`：最终可执行命令、配置字段、结果解读。
- `tests/unit/test_real_model_load_harness.py`：解析器、预算与停止逻辑的免费单元测试。

复用 httpx 异步流式客户端；第一版资源采样可使用 PowerShell Get-Process，不为压测直接引入 Locust/psutil 等依赖。脚本单元测试允许模拟协议数据，但这类数据不得出现在真实性能报告中。

### 指标定义

| 指标 | 定义 |
| --- | --- |
| HTTP 建连/响应头时间 | 客户端发起到获得响应头，独立记录 |
| 首个 SSE 帧时间 | 可能只是 thread 帧，不代表模型开始或产生文字 |
| 首个文本事件时间 | 发起到第一个有内容的 text 帧；不得标为 token TTFT |
| 轮次总耗时 | 发起到合法 done 终态；同时检查此前是否 error |
| 容量/会话锁等待 | 服务端分别记录 semaphore 与 thread lock 的等待区间 |
| 模型调用耗时 | 每次 invoke 开始到结束；SDK 内重试须另计，无法细分时明确标注 |
| 收尾耗时 | after-hook、持久化等独立区间；不能用总耗时减模型耗时猜测 |
| 正确性 | 跨会话污染、重复消息、半轮落库、取消后恢复、SSE 协议异常 |
| 资源与费用 | 服务端及子进程 CPU/内存/句柄、真实在途调用数、数据库/日志大小、usage、供应商账单 |

用单调时钟记录耗时；跨进程关联使用 run_id、client_request_id、thread_id、turn 序号、调用 ID。现有普通审计日志没有完整细粒度请求关联，需显式补采，不能假定它已经具备。

调用级 usage 单独保存结构化数值，不复用会遮盖 token 字段且可能丢事件的审计通道；只记录计数、模型标识和供应商 request_id，不写 Authorization、密钥或完整模型请求。不得为此直接放宽全局敏感信息清洗。

### 客户端判定

- HTTP 200 但出现 error 帧：失败；error 后 done 不得改判成功。
- 连接关闭但没有合法 done：非正常完成；记录超时、主动取消、网络断开等原因。
- 支持 SSE 分块、跨块 UTF-8、空行分帧；不要假定一次网络读取对应一个 JSON。
- 主动取消单独统计；非主动超时和失败不能从分母删除。成功样本延迟与失败等待时间分表报告。
- 每档报告样本量、p50/p95、最大值及错误数；少样本不作可靠 p99 承诺。基线 10 次只是校准，正式比较须使用相同场景并重复采样。

验证：解析器覆盖 error→done、截断流、空文本、超时和取消；预算测试覆盖并发预留、辅助调用、unknown usage 与在途任务排空。默认 CI 不读取密钥、不调用真实模型。

## 6. Phase 3：分档执行真实模型场景

采用闭环并发：一个虚拟用户结束当前轮次后再发下一次，另设符合账号配额的全局发起速率上限。不用无限任务堆积模拟高并发；该结果表示交互负载能力，不声称是固定到达率容量。

| 阶段 | 客户端并发 | chat 上限 | 验证重点 |
| --- | --- | --- | --- |
| 预热 | 1 | 3 | 初始化、连通性、计量；费用计入、耗时单列 |
| 基线 | 1 | 10 | 固定短输入，校准耗时、费用和输出限制 |
| 独立会话阶梯 | 1 → 2 → 4 | 每档 20，共 60 | 每轮独立 thread，排队与吞吐变化 |
| 同会话干扰 | 最多 6 | 24 | 每批 3 个同 thread 请求加 3 个独立请求，共 4 批；观察锁及容量占用 |
| 混合业务 | 4 | 40 | 聊天同时查询会话、历史和监控，读接口不阻塞 |
| 本地工具 | 2 | 20 | 指定隔离文件读写、工具循环及最终落库 |
| 取消与恢复 | 最多 4 | 取消 12、恢复 8，共 20 | 已进入真实调用后取消；等待在途排空再验证恢复 |
| 稳定性 | 2 | 最多 80，或 30 分钟先到者 | 长时间资源走势、日志/数据库增长与更新读取 |

默认总上限为 257 个 chat；实际模型尝试可能更多。可选并发 8 的 16 轮排队突发需纳入预算后再启用，总 chat 为 273。Web 容量仍为 4，不把队列等待直接判成缺陷。

固定使用不含私人信息的输入样本：短问答、给定文本摘要、受控多轮上下文、本地文件任务。保存样本版本/散列、输入长度与输出长度。不同上下文长度单独分组，不能把越聊越长的数据与短问答直接比较。

混合业务读请求建议总计不超过 2 次/秒，根据真实路由调用有界集合接口；监控始终带 limit=200，按 next_cursor 查更新。保留读请求数及服务端扫描量，不让读压测掩盖真实模型负载。

工具成功由文件实际内容、路径和会话历史验证，不能只相信模型说“已写入”。同会话并发检查串行执行与完整轮次，不假定网络到达顺序就是锁获取顺序。

取消场景须等到调用级探针确认模型调用已开始，不能以收到 thread 帧为依据。供应商调用未结束时不立即重试原业务；设置有限排空期限，超期记失败并停止升压，保留费用预留。

稳定性阶段如果提前达到 80 轮，报告真实运行时长，不能称“30 分钟稳定性通过”。测试客户端资源与服务端资源分别记录。

### 停止条件

- 任意串会话、半轮落库、意外修改测试区域外文件：立即停止新请求并保存证据。
- 连续 3 次供应商 429，或至少 20 次尝试中 429 比例超过 10%：停止升压，按供应商提示退避，不持续重试冲配额。
- 连续 3 次非预期服务端 5xx、服务无响应、无法排空在途请求：停止该阶段。
- 金额、调用次数、时间或预设资源上限任一触达：停止准入并收尾；费用安全优先于完成样本数。

## 7. Phase 4：验收判定与瓶颈归因

以下为本地桌面使用的建议标准，执行前固定，不在看到结果后放宽。

| 类别 | 判定 |
| --- | --- |
| 数据与隔离 | 零串会话、零重复持久化、零半轮提交；任何出现均阻塞验收 |
| 终态 | 正常请求终态完整；故障可见；取消后可继续新轮次，不遗留永远占用的会话锁 |
| 成功率 | 无故障注入场景单列应用失败与供应商失败；该小样本验收要求零未解释应用失败，不据此宣称生产 99.9% 可用性 |
| 读接口 | 同机建议 p95 ≤ 500 ms；受控模型负载下仍可查询历史和监控。未满足先定位，不把此数字说成已有 SLA |
| 聊天响应 | 先给出真实并发 1 基线；相同样本下并发 2/4 的 p95 超过基线约 2 倍时启动归因，不直接归咎项目 |
| 资源 | 在途调用可收敛，句柄不持续累积；内存按稳定窗口观察，缓存高水位不直接定性为泄漏 |
| 成本 | 调用级实际模型与 usage 可追溯；unknown 项单列，账单与估算差异有说明 |

供应商变慢/429：记录账号与模型的容量边界；不能通过换更快模型“证明”本次应用优化有效。锁等待或本地收尾慢：用服务端计时定位后再提出最小修复。没有对应探针时结论写“未能归因”，不填推算值。

若需要改进，一次改变一个因素，在相同模型、输入、依赖、并发与预算下复测，至少重复两轮观察波动。效果未超过波动时不声称优化有效；不得通过少持久化、跳过校验或丢事件换性能。

真实浏览器另补一个小型验收：发送、停止、切换会话、错误可见、删除确认、监控更新。API 压测不能替代这些交互。该部分产生的真实调用也计入总预算。

## 8. Phase 5：证据、回归与交付

拟输出到独立结果目录，不默认提交原始数据：

- manifest.json：源码/依赖/机器/非敏感配置、负载和预算。
- turns.jsonl：轮次耗时、终态、错误分类、关联 ID。
- calls.jsonl：全部真实调用的模型、耗时、usage、重试/取消/unknown 状态。
- resources.csv：建议每秒采样的服务端资源和在途量。
- summary.md：每档样本数、延迟、吞吐、正确性、费用核对及验收结论。

报告明确区分：实测、估算、未验证、测试配置与日常配置的差异。原始提示词/完整回复默认只存散列和长度；敏感标识做必要脱敏。

交付前先跑压测工具免费单元测试，再按项目 CI 的真实配置执行相关回归、lint/type 检查和 diff 检查。付费压测仅手动显式启用，不接入默认 CI；不能把脚本测试通过写成真实压测通过。

最终结论限定为下列一种：

1. **按指定本机、模型、并发范围验收通过**：正确性和已约定体验门槛通过，保留容量与成本边界。
2. **有条件验收**：低并发可用，但上游限流或预算不足导致更高档位未验证，列明允许范围。
3. **暂不验收**：存在数据一致性、取消后无法恢复或不可解释的本地错误，附复现与修复清单。

本方案本身不代表性能通过。下一步是实现隔离启动器、调用计量与预算保护，填写实际供应商/模型及金额上限，再从 13 轮预热和基线开始。
