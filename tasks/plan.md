## 3. 已认可的七项优化

### A1. 草稿可靠恢复

用户效果：没有发送完的问题，切换会话、隐藏窗口或重新启动后仍可接着写。

实施切片：
1. 定义有版本的本地草稿记录：会话标识、窗口来源、文字、图片引用、相关输入选项和更新时间；显式处理尚未分配真实 thread_id 的新会话。
2. 工作台和小窗分别接入保存/恢复，保留各自草稿，不用一个 localStorage 键相互覆盖；外部变化有提示，不静默替换正在编辑的文字。
3. 提供清除入口、数量/字节上限和失败提示；上传中的图片不当作已保存。与现有图片草稿清理机制协调，恢复时检查引用，失效则提示重新添加。

验收：
- [ ] 正常草稿的文字、图片归属与选项在会话切换及重启后恢复，发送成功后仅清理对应草稿。
- [ ] 两窗口编辑、慢上传、保存失败与新会话转正式会话时不串草稿、不重复发送。
- [ ] 清除操作可用；私密草稿默认不新增持久化，并说明这不等于把现有“个人记忆”开关扩展为整个应用的无痕承诺。

依赖：无。主要落点：共享前端草稿模块、index.html、quick.js、ui_common.js；必要时对图片草稿引用做小范围后端适配。

### A2. 长回答阅读体验

用户效果：向上阅读时不会被新文字拉走；长回答更新更平稳，代码可以单独复制。

实施切片：两窗口使用一致的底部跟随判定与“有新内容 / 回到最新”入口；展示层合并高频刷新，收尾强制补齐最后内容；代码块增加独立复制和成功/失败反馈。

验收：
- [ ] 用户主动向上滚动或选择文字时保留视口；回到底部后恢复跟随，两窗口行为一致。
- [ ] 最后分块、错误/停止说明和历史重绘保持完整，切换会话不把上个会话的渲染回调写入新会话。
- [ ] 代码复制准确，原有整段复制、Markdown 安全限制和减少动态效果偏好保留；不把渲染优化宣称为模型响应变快。

依赖：无，可在 A1 后接入。主要落点：共享展示 helper、index.html、quick.js、markdown.js/css。

### A3. 历史全文搜索

用户效果：输入以前讨论过的词，看到命中片段并回到对应消息。

实施切片：
1. 核对 ConversationStore 的持久消息键与 SQLite 实际功能，提供参数化、分页、有上限的本地搜索；中文匹配单独验证，不假设默认分词器天然满足中文检索。
2. 现有搜索入口显示会话标题、消息片段和命中位置；定位尚未加载的消息时按需读取附近历史，不一次下载全部会话。
3. 会话删除后移除对应搜索数据；若使用可重建索引，恢复/迁移后核对同步规则。

验收：
- [ ] 未加载到侧栏的旧会话也能被搜索到，中文、特殊字符和空查询语义明确。
- [ ] 点击结果能定位正确会话与消息，分页稳定；删除会话后不再命中。
- [ ] 搜索不调用模型，不把所有历史加载到浏览器；失效结果有可恢复提示。

依赖：无；与 A1 的草稿会话键保持一致。主要落点：state_machine.py 中存储层、搜索路由/模型、workspace.js、index.html。检索与消息定位分别实施，避免一次扩大历史接口。

### A4. Agent 执行记录

用户效果：不用打开原始日志，也能知道这一轮在做什么、哪里失败。

实施切片：将当前工具标签升级为默认折叠的执行记录；补齐轮次/工具调用关联与真实起止时间，再接入工作台和小窗；阶段名称只在对应事件真实存在时显示。

验收：
- [ ] 工具调用、返回、失败和取消能正确关联；重放/重连不重复，历史缺少数据则明确标注。
- [ ] 时间来自实际事件，不伪造进度百分比、预计剩余时间、模型内心推理或未发生的检查。
- [ ] 内容经过现有脱敏与安全展示，详情按需读取且有上限，普通聊天不被大量标签占满。

依赖：复用已完成的有界实时同步。主要落点：agent.py/审计或流事件契约、live.py、共享执行记录 UI；先交付事件关联，再交付 UI。

### A5. 记忆就地纠正

用户效果：发现回答引用了不合适的个人信息，可以从该条依据直接纠正。

实施切片：本轮记忆展示增加“纠正”和“前往管理”；读取最新正文与 revision 后调用现有治理接口，展示保存后的结果；旧回答保留“当时使用的版本”含义，不伪装成过去从未用过旧内容。

验收：
- [ ] 编辑定位正确 memory_id/scope，旧 revision 冲突不覆盖，失败保留用户草稿。
- [ ] 已删除/禁用或已被替换的记录不能被旧消息入口复活，后续召回遵守现有规则。
- [ ] 两窗口可操作；五层内核、确认机制、MEMORY.md 投影和墓碑语义保留。

依赖：无；可与 A4 的关联标识一起核对。主要落点：ui_common.js、index.html、personal_ui.js；优先复用治理 API。

### A6. 稍后提醒

用户效果：收到提醒时可以直接完成，或选择 10 分钟/1 小时后再提醒。

实施切片：为“当前这一次提醒”定义单独的延后状态与 occurrence 标识；调度器处理延后投递；在现有日程/未读卡片加入操作，系统通知入口仅在原生接口确实支持时接入。

验收：
- [ ] 延后不覆盖事项原始时间、不移动重复日程后续周期，也不把“延后”当“完成”。
- [ ] 重复点击、跨重启、过期通知和完成/删除竞态不会产生重复有效提醒。
- [ ] 展示下次实际提醒时刻和本机时区；程序关闭期间的能力边界如实保留，不承诺离线仍通知。

依赖：现有日程 CRUD。主要落点：schedules.py、调度/通知接线、personal_routes.py、personal_ui.js；状态/调度与前端分开交付。

### A7. 本地备份与恢复

用户效果：升级或换设备前，可以保存个人数据；恢复前能看清将发生什么。

分三个独立切片：
1. **A7a 备份**：用户主动选择目标；清单覆盖会话、有效记忆正文及必要治理元数据、日程、个人设置和关联图片/自定义图标。排除密钥、日志、EXE 和任意工位文件；候选记忆、其他材料是否包含必须在清单中明确。SQLite 使用受支持的备份方式，跨文件快照需阻止并发写入或拒绝在活动任务期间开始，不能直接复制活动数据库冒充一致快照。
2. **A7b 恢复预览**：先校验版本、大小、清单、路径与内容，再展示数量/范围。拒绝路径穿越、符号链接等逃逸及不兼容包，不因解压自动执行文件。
3. **A7c 安全应用**：用户确认具体预览后，在没有活动任务的维护状态下先备份现状再恢复；失败保留现状和恢复证据。默认不从聊天历史自动重新抽取记忆，本机恢复保留当前删除屏障，防止旧备份复活已删除记忆。跨版本或跨机器若不能保留语义，明确拒绝而非猜测合并。

验收：
- [ ] 在隔离数据上完成“备份→预览→恢复”，会话图片、日程和记忆治理状态一致，凭据没有进入备份。
- [ ] 损坏/超大/恶意/旧版备份、磁盘写入失败和正在运行的任务有明确处理，不破坏原数据。
- [ ] 用户看到并确认恢复范围；旧备份不能绕过墓碑屏障，未通过预览不得替换现有工作区。

依赖：A1/A3/A6 的新增持久状态定型后纳入清单。主要落点：独立备份模块、个人路由、设置 UI、存储维护接线；三切片分别验证，不能用仅导出 MEMORY.md 代替完整备份。

## 5. NovaMind 特色能力候选（尚未批准实施）

这些方向不是“其他应用没有”的排他性宣称。特色来自把本项目现有审计、研究、记忆和日程能力组合成具体个人工作流。每项先做小闭环，来源不足就明确不足。

### B1. 事项接续：“我的论文上次做到哪了？”

场景：同一件事持续几周，散落在不同会话、文件和提醒里。用户不应该每次重新交代背景。

最小功能：用户主动将会话关联到一件事项。事项卡只保留目标、已确认进展、待解决问题、下一步、关联文件/会话/日程；再次打开时展示“上次停在这里”。进展关联可回看的来源，用户可修正和结束事项。事项属于可编辑工作记录，不默认写成永久个人记忆。

区别于通用聊天增强：把会话、记忆、成果与日程围绕同一件事接起来，服务毕业论文、求职、学习计划等长期个人任务。

落地基础/缺口：已有 thread、scope、摘要和日程引用；缺少用户可管理的事项对象与可靠关联。摘要不能单独充当事实真值。依赖 A1/A3/A5，有少量新增事项数据与 UI，不改核心循环。

首版验收：两个会话能接续同一事项；卡片每个已确认进展有来源；删除来源时标记失效，不从卡片恢复已忘记正文。不做后台无限推进或定期模型总结。

待验证假设：用户确实有长期事项，且愿意进行一次关联。若维护成本高于重复解释，先缩为“固定一张接续卡”，不发展成复杂项目管理系统。

### B2. 答案依据：“你为什么这样回答？”

场景：研究结论、生活建议或工作判断说得很肯定，但用户不知道依据是旧记忆、当前材料还是推测。

最小功能：回答下方的依据面板分别列出本轮实际使用的个人记忆（含版本）、用户提供材料和已关联工具结果，显示来源时间/可用性。针对重要结论，可进一步建立“结论→支持材料→待核对点”的引用关系；没有原文或无法验证对应关系时明确标注，不从 200 字日志摘要补造引用。

区别于 A4：A4 回答“做了哪些操作”；这里回答“这个结论依据什么、还有什么没查证”。不显示模型私有推理，不编造可信度分数，来源存在也不等同于结论已正确。

落地基础/缺口：已有记忆引用与工具审计；缺少端到端证据标识、可授权读取的原文片段和结论引用校验。先交付已知输入的依据清单，再评估结论级关联，不能把第一步宣传为自动事实核验。依赖 A4/A5。

首版验收：实际使用的记忆/材料可以回看；失效、截断、冲突与缺证据清楚可见；引用文字能在原材料定位。可选“核对这一点”必须用户触发，涉及模型/外网时先显示范围和费用约束。

待验证假设：审计信息足够关联来源；若不够，补最小证据记录，而不是长期保存所有输入和工具大正文。

### B3. 截图转安排：“把这张考试安排表整理进日程”

场景：课程表、考试通知、会议截图已经能上传，但手工逐项确认和创建提醒仍麻烦。

最小功能：用户选择“识别安排”后，先生成可编辑预览，逐条列出事项、日期/时间、时区、重复、提醒设置及对应截图文字。确认选中的条目后批量创建，返回成功/失败清单，并可回看原图；缺年份、时间歧义和低把握识别先询问，不擅自补齐。

区别于已有图片对话：把识别结果变成可核对的结构化操作，而非仅回复一段文本或直接创建全部日程。

落地基础/缺口：复用图片入口与日程 CRUD；新增“解析草稿→预览确认→幂等提交”流程。视实际视觉模型能力验收，不宣称任意模型都识图，不额外搭建 OCR 服务。依赖 A6。

首版验收：同一预览重复提交不重复建日程；只创建勾选条目；批量部分失败可恢复；原图只作为数据，图片中的指令不得绕过用户确认。

待验证假设：当前视觉模型识别日程字段可靠。先用用户提供或生成的非敏感样本人工核对，真实调用前确认预算。

### B4. 近况更新：“我已经入职了，别再按求职中理解我”

场景：偏好会变化，阶段性背景会过期，仅靠累积记忆容易出现自相矛盾。

最小功能：用户明确提出变化时，展示可能相关的旧记忆，提供“仅本轮适用 / 更新长期信息 / 两者属于不同场景”。定期整理入口由用户主动打开，展示重复、可能冲突、可能过时的条目和来源，逐条确认后才修改。

落地基础/缺口：已有来源、scope、revision 和替换/删除机制；缺少面向用户的语义整理。依赖 A5，复用治理库，不另建“人格库”。时间久不代表内容错误，模糊冲突只是候选，不能自动删除或覆盖。

首版验收：一次性要求不会自动成为永久偏好；不同场景不被误合并；拒绝整理建议后不改变原记忆和召回状态。模型辅助整理只在用户主动触发时运行。

待验证假设：建议确有帮助且误报可接受；先支持明确更新与相关条目对照，再考虑批量语义检查，不做每次聊天都额外调用模型的后台扫描。

### B5. 成果验收单：“你说改好了，实际交付了什么？”

场景：Agent 修改代码、生成文档或安排日程后，用户需要检查成果，而不是只看到“已完成”。

最小功能：任务结束附一张折叠卡，列出实际生成/修改的文件、执行过的检查、检查结果和未完成项；支持查看工位内授权文件及可用差异。日程类任务展示真实创建/更新条目。区分工具调用成功、文件写入成功、检查通过与用户验收。

落地基础/缺口：已有受控工位、工具结果和审计；缺少完整变更清单与前后版本。先覆盖可观测的内置操作；不能从工具名称猜“成功”，不能把上下文快照当文件系统快照，不能承诺对外部命令/接口任意一键回滚。依赖 A4。

首版验收：说“写入成功”能对应实际结果；未检查则标注未检查；失败或权限外成果不伪装可查看。无证据的操作显示未覆盖，不制造测试报告。

待验证假设：现有工具面能稳定提供结构化结果。优先接一种实际文件写入路径，验证后再扩大覆盖面。

## 6. 新方向的取舍建议

推荐特色组合：**B1 事项接续 + B2 答案依据 + B3 截图转安排**。B1 服务跨天持续任务，B2 延续可审计/研究内核，B3 连接悬浮球、图片和日程，能直接减少日常操作。B4/B5 作为随后深化候选。

建议先做 A1–A3 稳定日常操作；用户选定候选后，再将 B1 的最小接续卡和 B2 的依据清单插入 A4/A5 附近，B3 安排在 A6 后。没有选定前不改变 A 队列，不预先实现 B 的新存储或路由。

本轮不建议添加新仪表盘、复杂多 Agent 编排、全天屏幕监听、自动读取全部剪贴板、无人值守研究、云同步或训练个人人格模型。它们会扩大隐私/费用/维护范围，对当前个人用途的收益尚未证明。保留现有深度研究、设计、编码和生活场景，不把应用收窄为专用研究工具。

界面统一原则：复用现有圆角、色彩、图标、浅深主题与短动效；接续卡、依据、成果默认折叠，动作按情境出现；悬浮球维持轻入口，复杂预览在小窗或工作台展开。特色体现在任务闭环，避免靠更多常驻按钮表达能力。
